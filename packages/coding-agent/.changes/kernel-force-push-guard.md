- Added a force-push guard to the kernel bash tool: `git push` invocations carrying a force flag (`--force`, `-f`, bundled short options, a `+`-prefixed refspec) are refused before execution when their target names main/master or `@{u}`-style refs, when `--all`/`--mirror` would rewrite every branch, or when the refspec is implicit and the probed upstream (`git rev-parse @{u}`, run only on a pattern match in the command's replayed cwd) exists; `--force-with-lease` and `--force-if-includes` are never refused, plain pushes pay nothing, and force-pushes the guard cannot check statically (globs, substitutions, xargs-fed refspecs, eval or quoted `sh -c` payloads, unreplayable `cd`/`git -C`/GIT_DIR relocations) are refused outright. Explicit bypasses: `bash(command, allow_force_push=True)` or `PI_BASH_ALLOW_FORCE_PUSH=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
- Hardened the kernel force-push guard against every bypass class found in review: the scan reads the command the way the shell does (backslash-newline continuations joined, quoted escapes folded, ANSI-C `$'...'`/`$"..."` bodies decoded, inline `-c alias.X=...` bodies expanded, `GIT`/`Git.exe`/`/usr/bin/GIT`/`SH` casing) and refuses anything it cannot resolve statically: a push argument holding a variable, glob, or substitution (`f=-f; git push $f ...` or `$BRANCH`), a URL or scp-style remote (whose implicit refspec is not a refspec), `env -C` / `env --chdir` / `env -S` wrappers, a git subcommand that is not a builtin (a repository or user alias, or an external `git-` program), an implicit refspec on a branch with no upstream (the target then comes from push.default, remote.<name>.push, or remote.<name>.mirror), and a command that ends in a line continuation. The allowed set is unchanged: `--force-with-lease`, `--force-if-includes`, `--dry-run`, force to a non-protected branch, plain pushes, and both documented bypasses.
