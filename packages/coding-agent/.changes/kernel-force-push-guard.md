- Added a force-push guard to the kernel bash tool: `git push` invocations carrying a force flag (`--force`, `-f`, bundled short options, a `+`-prefixed refspec) are refused before execution when their target names main/master or `@{u}`-style refs, when `--all`/`--mirror` would rewrite every branch, or when the refspec is implicit and the probed upstream (`git rev-parse @{u}`, run only on a pattern match in the command's replayed cwd) exists; `--force-with-lease` and `--force-if-includes` are never refused, plain pushes pay nothing, and force-pushes the guard cannot check statically (globs, substitutions, xargs-fed refspecs, eval or quoted `sh -c` payloads, unreplayable `cd`/`git -C`/GIT_DIR relocations) are refused outright. Explicit bypasses: `bash(command, allow_force_push=True)` or `PI_BASH_ALLOW_FORCE_PUSH=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
