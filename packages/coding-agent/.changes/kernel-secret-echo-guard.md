- Added a secret-echo guard to the kernel bash tool: a bare environment dump (`env`, `printenv`, `export -p`, and flags-only forms such as `env -0`) or a `cat`/`echo` of a known secret file under the home directory (`~/.ssh`, `~/.gnupg`, `~/.aws/credentials`, in either the `~` or the `$HOME` spelling) is refused before any process starts, because that output persists in session logs that models and users read later. The dump test is shell-faithful: leading `FOO=1` assignments are stripped first (`FOO=1 env` is a bare dump in disguise), redirections are ignored because they never narrow what is printed (`env 2>/dev/null`, `env 2>&1`, `env > /tmp/x`; a `&` glued to `>` is a redirect spelling, not a background operator, so `env 2>&1 | grep PATH` stays a piped read), and quoted command words and concatenations are canonicalized (`"env"`, `ca"t"` still run the command); `$HOME` glued to a secret path matches even across a closing double quote (`cat "$HOME"/.ssh/id_rsa`). Single-quoted spans and comments are masked so echoed strings and quoted data stay inert, while quoted operands stay single words (`env 'foo&bar'` stays an executor form). A bare dump piped into `grep` is still allowed as the targeted read the refusal suggests, narrowed to a fixed-string single-key filter: an inverted (`-v`), file-supplied (`-f`), context-widening (`-A`/`-B`/`-C`), empty, or regex pattern is refused, while `-F`/`--fixed-strings` and other bounded flags pass; `.env`-class files, directory listings, `printenv VAR`, `env FOO=1 cmd`, and `export FOO=1` are never matched. Explicit bypasses: `bash(command, allow_secret_echo=True)` or `PI_BASH_ALLOW_SECRET_ECHO=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
