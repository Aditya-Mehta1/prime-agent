- Added a secret-echo guard to the kernel bash tool: a bare environment dump (`env`, `printenv`, `export -p`, and flags-only forms such as `env -0`) or a `cat`/`echo` of a known secret file under the home directory (`~/.ssh`, `~/.gnupg`, `~/.aws/credentials`, in either the `~` or the `$HOME` spelling) is refused before any process starts, because that output persists in session logs that models and users read later; single-quoted spans and comments are masked so echoed strings and quoted data stay inert, a bare dump piped into `grep` is still allowed as the targeted read the refusal suggests, and `.env`-class files, directory listings, `printenv VAR`, `env FOO=1 cmd`, and `export FOO=1` are never matched. Explicit bypasses: `bash(command, allow_secret_echo=True)` or `PI_BASH_ALLOW_SECRET_ECHO=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
