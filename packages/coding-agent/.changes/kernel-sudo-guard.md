- Added a privilege-escalation guard to the kernel bash tool: sudo/doas command words are refused before any process starts, because silent privilege escalation outranks every other guard on passwordless-sudo setups. Covered: any path spelling, quoted-fragment forms (`su"do"`, `"sudo"`), wrapper chains (env/nice/timeout/nohup/setsid/exec/busybox, including `exec -a NAME`), assignment prefixes, redirections, group/subshell/brace and compound-command positions (`if`/`then`/`elif`/`else`/`while`/`until`/`for`/`do`/`case` bodies), pipelines (`echo x | sudo tee /etc/hosts`), xargs operands (including shell payloads behind them), interpreter `-c`/`eval` payloads, quoted `$(...)`, backtick, and process-substitution (`<(cmd)`, `>(cmd)`) payloads, and heredoc bodies owned by a shell. Lookup forms (`command -v sudo`, `command -V sudo`, `which sudo`) stay allowed, and `command` itself stays gated to those lookup flags instead of short-circuiting the walk, so `command sudo id` is refused; operand mentions (`man sudo`, `grep sudo file`), data heredocs, and comments stay allowed; unresolvable command-position words (`$CMD id`, `$SUDO id`) fail closed. Out of scope: `su`, trap actions, other interpreters' string payloads (`python -c`), Windows runas, and script-file contents. Explicit bypasses: `bash(command, allow_sudo=True)` or `PI_BASH_ALLOW_SUDO=1`, where the environment bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard; they are ignored and warned about loudly.
