- Added a recursive chmod/chown guard to the kernel bash tool: `chmod`/`chown` invocations carrying a recursive flag (`-R`, `--recursive`, bundled short options, flags in any position) are refused before execution when an operand resolves outside the current workspace (HOME itself, `/`, parent directories, other trees, symlink escapes), names a protected dot path (`.git`, `.env`-class dotfiles and dot-directories), or cannot be checked statically (globs, substitutions, unknown variables); quoted command words and flags scan like their unquoted forms, and `eval`, `sh -c`, `xargs`, and unreplayable `cd` wrappers are refused outright. Hardened against red-team bypasses of the first cut: command names built from variables or command substitutions (`$cmd -R ...`, `$(printf chmod) -R ...`, including behind xargs/sudo/env and similar executors), ANSI-C quoted command names, flags, and operands (`$'chmod' $'-R' ...`, plus `$"..."` locale quoting), GNU's abbreviated `--recursive` prefixes (`--rec` through `--recursiv`), nested or mixed quoted wrappers (`eval`/`sh -c` one inside another, quoted payloads rescanned one layer at a time), process substitutions feeding a shell wrapper (`bash <(...)`), and BASH_ENV (an inherited BASH_ENV/ENV is stripped from the kernel child environment, and arming BASH_ENV from the command is refused); relative `cd` relocations are refused while CDPATH is armed (inherited or assigned in the command) because bash searches CDPATH directories first, and the xargs walk no longer misreads an operand named `xargs` or a later `xargs` pipeline as wrapping a first-word recursive chmod. Explicit bypasses: `bash(command, allow_destructive_chmod=True)` or `PI_BASH_ALLOW_DESTRUCTIVE_CHMOD=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
