- Added a recursive chmod/chown guard to the kernel bash tool: `chmod`/`chown` invocations carrying a recursive flag (`-R`, `--recursive`, bundled short options, flags in any position) are refused before execution when an operand resolves outside the current workspace (HOME itself, `/`, parent directories, other trees, symlink escapes), names a protected dot path (`.git`, `.env`-class dotfiles and dot-directories), or cannot be checked statically (globs, substitutions, unknown variables); quoted command words and flags scan like their unquoted forms, and `eval`, `sh -c`, `xargs`, and unreplayable `cd` wrappers are refused outright. Hardened against red-team bypasses of the first cut: command names built from variables or command substitutions (`$cmd -R ...`, `$(printf chmod) -R ...`, including behind xargs/sudo/env and similar executors), ANSI-C quoted command names, flags, and operands (`$'chmod' $'-R' ...`, plus `$"..."` locale quoting), GNU's abbreviated `--recursive` prefixes (`--rec` through `--recursiv`), nested or mixed quoted wrappers (`eval`/`sh -c` one inside another, quoted payloads rescanned one layer at a time), process substitutions feeding a shell wrapper (`bash <(...)`), and BASH_ENV (an inherited BASH_ENV/ENV is stripped from the kernel child environment, and arming BASH_ENV from the command is refused); relative `cd` relocations are refused while CDPATH is armed (inherited or assigned in the command) because bash searches CDPATH directories first, and the xargs walk no longer misreads an operand named `xargs` or a later `xargs` pipeline as wrapping a first-word recursive chmod. A second red-team round is also closed: quote- or ANSI-C-encoded wrapper names (`e"val"`, `b"ash" -c`) trigger the wrapper payload scans through the parsed words instead of raw-text regexes; glob/brace-expandable command words (`chmo?`, `{ch,}mod`) are refused; here-document bodies are masked through their terminator so an unmatched quote in the body cannot hide a later real command (here-strings stay visible to the wrapper-fed checks); shell function definitions and alias bodies that can carry a recursive chmod (`f() { chmod "$@"; }; f -R 755 /`, `alias x='chmod -R 755 /'`) are refused; wrapper options before a process substitution (`bash -- <(...)`) and wrapper stdin fed by a pipe or here-string (`printf ... | bash`, `bash <<< ...`) are refused; and the CDPATH exemption now matches bash exactly (only `.`, `..`, `./`, `../` prefixes skip CDPATH; dot-named targets like `.config` still consult it). A third red-team round is also closed: here-document bodies that execute as shell code — a wrapper fed by the heredoc (`bash <<EOF ... EOF`, scanned with the full guard so in-workspace recursion stays allowed) or a heredoc flowing out of a command substitution (`eval "$(cat <<EOF ...)"`) — are scanned instead of staying masked; wrapper option arguments (`bash -o vi <(...)`, `bash --rcfile <(...)`) no longer hide a process substitution from the wrapper check (any input-feeding marker in the wrapper's command region refuses it); function bodies in subshell form (`f() (chmod "$@"); f -R ...`) are refused like brace bodies; and a trailing heredoc operator is a shell syntax error instead of a guard crash. Explicit bypasses: `bash(command, allow_destructive_chmod=True)` or `PI_BASH_ALLOW_DESTRUCTIVE_CHMOD=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
